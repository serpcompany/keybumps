# Agent instructions: keybumps.app website

`apps/web/` is the public keybumps.app site: Next.js 16 on Cloudflare Workers through OpenNext, with pnpm 10 and Node 22 (`.nvmrc`). Run site commands from this directory. The Mac app lives in `apps/macos/`, and website work never changes it. The repo-wide rules in the root [`AGENTS.md`](../../AGENTS.md) apply here too, including never taking over the owner's screen (computer use, browser control, or other screen control) without an explicit handoff; its Mac app rules don't.

- Follow the SERP Next.js website SOP as adapted for Keybumps in [serpcompany/keybumps#105](https://github.com/serpcompany/keybumps/issues/105). [`docs/agents/web.md`](docs/agents/web.md) is the website agent guide: commands, verification, environment configuration, canonical URLs and hosts, and analytics.
- Website PRs change only `apps/web/**`. Release-please skips a commit only if every file it touches is under `apps/web/`; a commit that also touches a root file counts as an app change and can bump the app version and reach `CHANGELOG.md`. If a root file must change, do it in a separate `chore:`, `docs:`, or `ci:` PR.
- Analytics run in production only, never in development, preview, or staging.
- Checkout, session, and license data in a URL must never reach analytics. `/thanks/` gets Polar's customer-session token, and `/license/` is the license-help page; both live in the separate `src/app/(sensitive-url)/` root layout. Each of those pages redirects a request that has a query to its bare URL before rendering (`src/lib/sensitive-url.ts`), the layout also strips any query in `<head>`, before the router or GTM can start (`src/components/strip-query.tsx`), and it sends no referrer. Only the two root layouts render `<Analytics />`, and there is no shared `src/app/layout.tsx`. Every RSC request for these pages is rewritten to a 404 (`src/lib/sensitive-url-routes.ts`), which Next.js turns into a full page load, so the router never renders them client-side. Nothing may link to them with a query (GTM's click triggers record the `href`), and links to them set `prefetch={false}`. The `(sensitive-url)` group holds only its layout and two pages: no `loading.tsx`, `Suspense`, or segment config, which would make the redirect stream as a 200. The global 404 never loads analytics. These pages read their query only to redirect it away. `src/lib/analytics-scope.test.ts`, `scripts/smoke.sh`, and `pnpm test:leak` enforce it.
- `pnpm test:leak` (`scripts/leak-test.mjs`) builds a production-mode site, serves it locally, and drives headless Chrome through every navigation that could expose `/thanks/` or `/license/` query data to GTM. The protection relies on Next.js router internals, so it must pass on every Next.js or OpenNext upgrade, and before merging any change to those pages, their layout, `next.config.ts`, or `src/lib/sensitive-url*.ts`. It needs Google Chrome installed (or `CHROME_PATH`) and isn't part of CI.
- Do not log or commit user content. On the site that also means form input, email addresses, license keys, checkout or customer details, and URLs with query strings. Logs hold only structural state, timing, and error category.
- Site tests are Vitest (`src/**/*.test.ts`) and run through `pnpm test`. They don't use Swift Testing.
- `pnpm install --frozen-lockfile && pnpm check` must pass before a PR. [`.github/workflows/web.yml`](../../.github/workflows/web.yml) runs on every pull request to `main` and in the merge queue, and runs the same check when the change touches `apps/web/`, the release notes `/changelog/` is built from (`docs/releases/v*.md`, `CHANGELOG.md`), a workflow file the site's tests read, or `.github/scripts/pr-touches.sh`; it never deploys.
- Follow the branch, PR, and review cycle in [`docs/development-workflow.md`](../../docs/development-workflow.md). Website work needs no Mac QA candidate (`apps/macos/scripts/build-qa-candidate.sh`). Report build, deterministic tests, `pnpm preview`, deployed and smoke-tested, and owner acceptance separately.
- Every current route (`/`, `/changelog`, `/download`, `/license`, `/plugins`, `/pricing`, `/privacy`, `/refunds`, `/terms`, `/thanks`) is an external contract and must keep resolving, directly or through at most one 308, per #105. In particular, shipped app builds link to `https://keybumps.app/pricing` (`apps/macos/Keybumps/Licensing/LicenseModels.swift`), builds with Settings › Plugins' Browse on keybumps.app button open `https://keybumps.app/plugins` (`apps/macos/Keybumps/Capabilities/PluginManifest.swift`), and builds with Settings › Changelog's View all releases button open `https://keybumps.app/changelog/` (`apps/macos/Keybumps/Updates/Changelog.swift`). Each plugin's page, `/plugins/<slug>/`, is linked from there and listed in the sitemap. `scripts/smoke.sh` checks each one; the redirects live in `src/lib/redirects.ts`. The one exception is `/download/`, which has no page: `src/app/download/route.ts` answers with a temporary 302 (never 308, and `no-store`) to the current DMG from `latest.json`, so `/download` takes one 308 to `/download/` and then that 302. Download buttons link to the DMG directly through `DownloadLink` (`src/components/download-link.tsx`), never to `/download/`.
- Do not deploy, change Cloudflare, or change the Polar checkout configuration without fresh owner authorization. An agent's merge under the root `AGENTS.md`'s listed paths authorizes the deploy that follows it. Deploys run only through CI (`.github/workflows/web-deploy.yml`) after a merge to `main`. Never run `pnpm deploy:staging`, `pnpm deploy:production`, `wrangler deploy`, `wrangler versions upload`, or `wrangler rollback` by hand; `wrangler deploy --dry-run` is fine. The CI token may touch only `keybumps-web-staging` and `keybumps-web-production`. The domain cutover in [`docs/agents/web.md`](docs/agents/web.md#domain-cutover) is the owner's to run.
