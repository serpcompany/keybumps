# Architecture

`KeybumpsApp` and `AppModel` own composition and lifecycle. Feature services own behavior but never create another app delegate, status item, Settings scene, updater, licensing controller, or launch-at-login controller. `AppModel.forLaunch()` returns the normal composition unless `-KBUITestPermissions` is present; the UI test composition in `UITestComposition.swift` fakes every permission, event tap, hot-key, audio, and user-folder boundary and keeps data in a disposable sandbox (see `testing.md`). Unit tests build their own compositions. Under the unit-test host (`UnitTestHost`: a Debug build that XCTest loaded, never Release, a QA candidate, or a UI-test launch), `ProductPaths` resolves the owner's folders into `UnitTestHost.dataDirectory`, a per-run temporary folder, so every store built with its default location keeps its data there.

Each capability is a first-party **capability module** under `apps/macos/Keybumps/Capabilities/`, registered by the app shell rather than hand-wired across enums and views. A module has two halves:

- A static `CapabilityDescriptor`: title and icon; required permissions; dependencies on other modules; an optional Command Palette tab (Command-number, name, icon, prompt, primary and secondary actions, and a `dataSource` when the tab lists another module's data, as the Screenshots tab lists Clipboard History entries); an optional Settings page with its disable explanation; and the update-safety critical operations it reports.
- A runtime `CapabilityModule` that owns its resources. `apply` registers or releases its shortcuts and starts or stops its resources for the current enabled set, `deactivate` runs immediately before it is turned off, `permissionsDidRefresh` resumes resources waiting on a permission, and `attentionCount` reports Settings attention, including setup that isn't a TCC permission (Screenshot Tools' Requires Clipboard History and folder access denied). A module can also contribute to another module's surface: Screenshot Tools sets the Clipboard tab's Command-E / Command-click edit action while it is enabled.

`CapabilityCatalog.descriptors` fixes registry order: the Settings sidebar order, with every module after the modules it depends on, so a dependency is settled before its dependents apply. `AppModel` builds one `CapabilityRegistry` with exactly one module per descriptor, in that order. The registry applies modules in order, deactivates the one being turned off, and runs permission-refresh recovery in reverse order, which is the pre-registry order (Shortcut Coach retries its detector before Window Manager re-arms drag-to-snap). Modules register shortcuts only through `CapabilityContext.configureShortcut`, which goes to `GlobalShortcutCoordinator`; their permissions are declared on the descriptor and resolved by `PermissionSetupPlan` and `PermissionCoordinator`; and they report to `UpdateInstallationSafetyPolicy` only through a `CapabilityUpdateSafety` limited to their declared operations. Palette tabs appear in Command-number order. `Capability`, `CommandPaletteTab`, and `SettingsSection` remain stable identifiers: `Capability` raw values are the saved preference IDs (`AppPreferences.knownCapabilities` still enables a newly introduced module once for existing installs), and the other two are launch-argument and accessibility tokens. Their presentation comes from the descriptors. Onboarding, Permissions, and General are fixed shell surfaces. Adding a capability means adding its identifiers, writing a descriptor and module, and registering it. The contract is internal and first-party; there is no public extension API, and third-party extensions are a non-goal.

`UpdateControlling` is the single app-shell update seam. The production adapter owns Sparkle's standard updater controller and exposes only customer-visible state/actions to `AppModel`, the native menu, and General settings. It explicitly opts into Sparkle's standard scheduled-update driver, which owns the linked release-notes and update presentation. Debug/test builds are disabled unless explicitly pointed at a credential-free, fragment-free loopback fixture feed. The shared `UpdateInstallationSafetyPolicy` is the one classification seam used by synchronous Window Manager commands, drag-to-snap while a window is actually moving, and Sparkle's supported relaunch-postponement callback; it combines Dictation phase with named app-owned critical operations, then resumes installation only when all are safe. A quit the user asks for is never blocked by momentary window actions or drags: `quitConfirmationReasons` names only work that quitting would lose (unsaved Screenshot Editor changes, Dictation in progress), and `AppDelegate` asks the user to confirm instead of silently refusing. The Screenshot Editor is the only unsaved-document workflow and reports `unsavedWork` while open; Clipboard, Quick Search, and Shortcut Coach do not own unsaved work. Structural update telemetry records only stage, version/build, elapsed time, and categorized failure—never user content, filenames, identity, or keys. For updates, release configuration embeds only the public feed URL and Sparkle's Ed25519 public key. The private key never enters the app or repository.

`LicenseControlling` is the single app-shell licensing seam (`docs/adr/0002-polar-native-license-keys.md`). It depends on a `LicenseProviding` protocol whose only implementation calls Polar's public customer-portal license-key API (activate, validate, deactivate) with the key and organization id; no secret is embedded. The controller keeps the key, its Polar activation id, and its last successful validation (the License Check) in the Keychain, revalidates every 24 hours (checked at launch, on wake, and hourly), honors it offline for 45 days, and publishes a `LicenseState`. `AppModel` starts capability modules only while that state is entitled; when Locked, it shows only onboarding, the License settings page, and Quit. Capability modules never read licensing state. Network or server failures never change the current state, and nothing licensing-related is logged. Changing providers means another `LicenseProviding` implementation and an app update.

The shared `GlobalShortcutCoordinator` is the sole Carbon hot-key registrar. `AppPreferences` persists the editable Quick Search, Clipboard History, Dictation, and Window Manager bindings; assigning one key combination removes it from any previous owner before the coordinator re-registers the complete valid set. During first-run onboarding only, `SpotlightShortcutConflictResolver` reads symbolic hot key 64 through the injected `SymbolicHotKeyPreferences` system boundary; when its enabled key and modifiers exactly match Quick Search, it preserves the entry and all siblings while disabling only that binding, asks macOS to reload symbolic hot keys, and retries Quick Search through `GlobalShortcutCoordinator`. Missing, malformed, unwritable, nonmatching, and completed-onboarding states fail closed or remain untouched as appropriate. Dictation temporarily registers unmodified Escape only while Recording or Transcribing can still be cancelled before insertion. `PermissionCoordinator` centralizes truthful permission state and recovery. It never caches: every refresh re-reads macOS. Changing Keybumps's Microphone access in System Settings restarts Keybumps (owner-observed), so the next launch reads the new state; a denied or restricted Microphone or Speech Recognition then recovers through System Settings rather than a native prompt macOS will not show again (`MicrophonePermissionFlowTests`). Each capability module stops its resources and releases its shortcuts when disabled. `ClipboardHistoryService` excludes only the exact pasteboard change written by automatic Dictation delivery, so a subsequent user copy—even of identical text—is still captured.

`ClipboardHistoryService` records each new item's source app through `ClipboardSourceTracker`, because macOS has no API that names the app that wrote the pasteboard. A Universal Clipboard item (`com.apple.is-remote-clipboard`) has none. Otherwise, an nspasteboard.org `org.nspasteboard.source` marker names the app (an empty marker means unknown). Without a marker, it's the app in front, which is sampled on every 0.45-second poll; if that app changed between two polls less than a second apart (⌘C then ⌘Tab), the app in front at the earlier poll wins. The system reader counts Keybumps as the app in front while one of its windows is key. That covers ⌘C in the non-activating Command Palette, which takes key focus without making Keybumps the frontmost app. Two of Keybumps' own controls whose writes reach Clipboard History also mark the write with its bundle identifier, since they can run after focus has moved on: the Screenshot Editor's Save, which copies the edited image, and the Dictation translation's Copy. Screenshot Tools ingestion records no source app. The key-window check itself is only exercised in the running app; unit tests cover the rule it feeds (`ClipboardSourceAppReader.appInFront`). The UI-test composition and the unit tests use `ClipboardSourceAppReader.inert` or a fake reader, and `AppModel`'s own default Clipboard History uses the inert reader under unit tests, so tests never read the app in front. `ClipboardSourceDomain` records the item's source domain when the app put the page's address on the pasteboard: Chromium's `org.chromium.source-url` (the tab's page), or else the main resource of WebKit's `com.apple.webarchive` (the frame the selection was in). It doesn't decode an archive larger than 8 MB (a rich copy's images travel in it), so that item gets no domain. It keeps only a website's domain name: the lowercased ASCII host of an http or https address, via `URLComponents.encodedHost`. So every international domain is stored in punycode (`xn--…`): browsers show lookalike domains that way but ordinary international ones in Unicode, and storing punycode means a lookalike is never shown as the domain it imitates. A trailing dot is dropped. Anything else outside letters, digits, dots, and hyphens is rejected, as are IP addresses, single-label names such as `localhost`, and local or special-use names (`.local`, `.test`, `.invalid`, `.internal`, `.arpa`). Other schemes record nothing, and the full address, path, query, and fragment are never kept, persisted, or logged. Universal Clipboard items get no domain. Browsers don't mark copies from private or Incognito windows, so those record their domain too. The source app's name and bundle identifier and the source domain are stored only in the local Clipboard History JSON (decoded as optional, so older history still loads) and are never logged. Clipboard tab search (`ClipboardEntry.matches`) matches the content anywhere, the app's name from the start of a word, and the domain from the start of a label other than `www` or its public suffix. That suffix is the top-level domain, plus a common second-level label under a two-letter country code, as in `co.uk` or `com.au`. So `com`, `co`, or `www` doesn't match every web copy. Other multi-label public suffixes aren't known, so a search can still match from their first label.

The Clipboard tab's `ClipboardRow`s are laid out like Raycast's rows. The preview is the item's kind: a thumbnail, or a `text.alignleft` symbol on the same tile. The rows show no kind word, though VoiceOver still announces it and search still matches `image` and `screenshot` for image items. The content fills the middle on one line, so every row is the same height: a text item's runs of spaces and newlines become single spaces, and an image with no file name shows its pixel size instead. Under it, a small gray timestamp is always the same width, `MM/dd/yyyy @ HH:mm` (or `hh:mm a` on a 12-hour clock) in `en_US_POSIX` with monospaced digits, from one cached formatter; VoiceOver reads it in the user's own date format. Right-aligned, from the right edge: a 24-point column holding the source app's icon (empty when there's no app or this Mac doesn't have it, so every row lines up), the app name, then the domain, in gray at the palette's 14-point accessory size. The group is capped at 360 points; the name and domain truncate, and the icon never shrinks. Only the selected image row shows Edit ⌘E, and only while Screenshot Tools is on, because the footer doesn't list it. Rows have no trash button: Delete (or Command-Delete while typing) removes the selected row, and each row also has a context menu (Copy, Edit for images while Screenshot Tools is on, and Delete) and a VoiceOver Delete action.

`AppShellLaunch` starts Keybumps once, at `didFinishLaunching`, with no dependence on any window: it starts the model (capabilities and global shortcuts), configures the Quick Search and app-shell routes, and installs the status item. macOS can relaunch Keybumps at login with no window, so nothing that keeps the app working waits for the main window to appear. `MainWindowRouter` retains the SwiftUI Settings-window opener configured while the initial window is alive. Before any window has existed, `MainWindowRouter.shared` asks macOS to reopen the app and flags that one reopen, so `AppDelegate` lets SwiftUI create the main window instead of routing to Quick Search. The status menu, Command-comma, and the Command Palette's Settings entries use that route, so closing Settings does not remove the only listener capable of recreating it. `QuickSearchRouter` separately retains the command-palette opener used by Dock reopen and the status item. The app uses one SwiftUI `Window` scene and disables automatic macOS window tabbing, so Settings routes reuse the same window while Dock clicks default to Quick Search.

`DictationTranscriptionCoordinator` owns the lifecycle of the selected local Whisper runtime below the completed-audio transcription seam. It coalesces a model's concurrent cold load, reuses that one runtime for nearby Dictation and History retries, and evicts it after five idle minutes or model replacement/deletion; normal process teardown releases it at application termination. Apple Speech remains outside that cache, and loading a replacement waits for the previous large runtime to unload.

`CommandPaletteController` owns one floating keyboard-first surface for Quick Search, Clipboard History, Screenshots, Dictation History, and Shortcut Coach History (labelled Hotkeys), styled by the shared `RaycastPaletteStyle` components (`PaletteTheme`, `PaletteKeycaps`, `PalettePillButtonStyle`, section headers, and `paletteFloatingSurface` for the floating footer pill and its round Settings button). Palette controls use the shared pill style: every button in the palette that isn't a row, tab, playback control, the footer pill, or the gear uses `PalettePillButtonStyle` (the footer pill's surface, a capsule or a circle for icon-only buttons, gray text that reaches full strength on hover, and red only on hover or press for destructive buttons); the Settings window keeps native macOS styles. Command-1/2/3/4/5 select those tabs in order; the Hotkeys tab is hidden unless `AppPreferences.showsHotkeysTab` is on or it was opened from Settings. In every tab, a round gear button at the footer's bottom left (Raycast's placement) and Command-comma open Settings through `CommandPaletteController.run(.keybumpsSettings)`, which closes the palette first; Quick Search's Keybumps Settings result takes the same path. Delete (or Command-Delete while typing) removes the highlighted Recent Item, clipboard item, screenshot item, or recording, and copies confirm with a notch notice after the palette closes. `PaletteHUD.shared` presents transient notch notices, one at a time, so a new notice replaces the current one. A separate `DictationIndicatorController` panel shows Dictation's live state in the same place; while it is on screen it holds the notch (`PaletteHUD.claimNotch`, a weak owner released on idle or after a failure hides), so other notices are dropped (Shortcut Coach tips still reach history) and one already showing is hidden. The notice is a click-through, non-activating panel centered on the camera housing (measured from `NSScreen.auxiliaryTopLeftArea`/`auxiliaryTopRightArea`, or a menu-bar tab without a notch) used by palette copies, the Screenshot Editor's Save, the Screen Recording warning, and Shortcut Coach tips; the Screenshots tab lays its items out in a three-column `ScreenshotGrid`, the Dictation tab is the list-and-detail `DictationPaletteResults`, and the Screenshots tab is a `ScreenshotPaletteContent` view over screen-capture Clipboard History items whose primary action opens the Screenshot Editor; tab chrome uses only the shortcut and name. History inputs consistently say Search, and one shared native SwiftUI `ClearAllButton` owns the visible `Clear All` label and destructive confirmation behavior. In every palette tab it is a compact pill in that style, labeled "Clear All" with no icon, that turns red only while hovered or pressed. Shortcut Coach enablement, filtering, displayed rows, and keyboard selection derive from one content model; its rows are passive and Return does not copy or mutate history. All three histories are presented and cleared from this surface instead of duplicating history management in Settings. The palette tracks its confirmation as an internal presentation, so sheet focus changes and alert-button clicks do not trigger outside-click dismissal. Clipboard metadata retains bounded JSON persistence; image payloads live as separate files under Application Support so the index stays small and deletion/eviction can remove media independently. `DictationHistoryService` owns the independently stored `~/Documents/Keybumps/recordings/<timestamp>/meta.json` and `output.wav` pairs. It persists recording/transcribing/completed/interrupted/failed lifecycle state, suppresses recovery of sessions known to be live in the current process, and converts stale pending or legacy playable audio-only folders into retryable interrupted entries after relaunch. Shared dictation cards provide retry transcription and adjustable local playback in the palette.

`DictationAudioTransportView` is the single visual playback component for original and translated speech. `TranslatedSpeechPlayer` selects an installed locale-matched voice, renders speech into a temporary local WAV, and composes the shared `DictationAudioPlayer`; closing or changing the translation stops playback and deletes the temporary file. Translated audio never enters the durable per-recording archive.

Shortcut Coach retains its donor separation between Detection, Infrastructure, Domain, and Views. One typed shortcut registry converts complete sanitized AX tuples into the durable event values consumed unchanged by history, the notch notice, keycaps, accessibility output, and the inline Shortcut Coach keyboard-symbol guide. The visible guide is a curated subset of Apple-documented menu symbols; broader runtime support does not automatically create repetitive or uncertain guide rows. Generic menu clicks resolve one exact enabled menu item from the hit ancestry, while Chrome tab actions poll the original application process for a bounded period so a moving button or one stale AX sample cannot lose the first verified action. `AppModel` records each detected action in history and then shows it as a notch notice through `CoachTipPresenting` (production: `PaletteHUD.shared`). There is no presentation setting: turning Shortcut Coach off is how to stop tips (late events are ignored), Send Test Suggestion shows the sample tip without writing history, and the old `selectedNotificationChannels` preference is removed on load. Shortcut Coach plays no sound, posts no macOS notifications, and needs no Notifications permission; the first launch after upgrading clears banners earlier builds left in Notification Center. Window frame calculations and the Rectangle-inspired settings grouping/preview model remain pure and separately testable from Accessibility execution. Dictation owns no guide or assistant behavior.

`ScreenshotToolsService` owns the Screenshot Tools capability under `apps/macos/Keybumps/ScreenshotTools/`. `ScreenshotLocationResolver` reads the macOS screenshot location read-only and falls back to the Desktop; a directory dispatch source plus a periodic location check detect new files, and only files carrying macOS's screen-capture metadata that were created after watching began and whose size has settled are handed to `ScreenshotClipboardDelivery`, which adds each file once through `ClipboardHistoryService.ingestImageFile(at:)` and, while `AppPreferences.copiesScreenshotsToClipboard` is on (the default), puts the new item on the pasteboard with `restore`, which marks that write as seen so it isn't added twice. It copies only when `ClipboardHistoryService.pasteboardChanged(since:)` reports no change since the file was created; that check records a copy the next poll would have caught first, so nothing copied after the file was created is replaced or lost, and it never reads the pasteboard while Clipboard History is stopped. The delivery's own copy passes `restore(_:countsAsCopy: false)`, so a newer screenshot still replaces an older one's copy. Clipboard History stores its own media copy plus the original `sourcePath`, never writes the pasteboard during ingestion itself, and never deletes the original. `ScreenshotToolsModule` runs the watcher only while both Screenshot Tools and its dependency, Clipboard History, are enabled; injected test compositions use an inert directory reader so tests never touch real user folders. `ScreenshotEditorPresenter` opens at most one `ScreenshotEditorWindowController` from the Command Palette's Clipboard tab (Command-E or Command-click, contributed by `ScreenshotToolsModule` only while Screenshot Tools is enabled). Annotations are value types in image points with snapshot undo; `ScreenshotAnnotationRenderer` is the single drawing path for both the canvas and export, rendering redactions from source pixels before marks and exporting at source pixel density. The open editor is reported to `UpdateInstallationSafetyPolicy` as `unsavedWork`. `ScreenshotCapturer` runs `/usr/sbin/screencapture` through an injected `ScreenshotCaptureRunning` (so tests never capture the screen), names files like macOS, and marks them with the screen-capture metadata so the watcher ingests them; the Screen and Edit hotkey adds every display's file through `ScreenshotClipboardDelivery.addForEditing` immediately, without copying (the editor's Save copies the edited image), and opens the main display's in the editor. Capture is gated on the Screen Recording permission from `PermissionCoordinator`. `SystemScreenshotShortcutTakeover` turns off macOS's conflicting ⇧⌘3/⇧⌘4 symbolic hotkeys through the same `SymbolicHotKeyPreferences` seam Quick Search uses for Spotlight, records only the IDs it turned off in `AppPreferences.takenOverSystemShortcuts`, and restores exactly those; test and UI-test compositions use `InertSymbolicHotKeyPreferences`. `AppPreferences` tracks known capabilities and known capability shortcuts so a newly introduced capability or shortcut is enabled once for existing installs and the owner's later choice is respected.

Quick Search owns a bounded local `RecentItemStore`. Only a successfully opened app, file, or folder becomes a recent item; opening it again moves the same URL to the front. The empty-search list opens the item directly and supports individual deletion plus confirmed Clear All. Its rows have no trash button: Delete removes the highlighted item, and each row has a context menu (Open, Reveal in Finder, Delete) and a VoiceOver Delete action. Revealing, highlighting, dismissing, failed opens, and ordinary typing do not add items. Quick Search also lists Quick Search commands (`QuickSearchCommand`; today only Keybumps Settings, shown with its ⌘, keycaps and the kind Command). `QuickSearchRanking.items` puts a command first when every query word is a whole word of its name or keywords (`settings`, `keybumps`, `preferences`, `prefs`), after the applications when the words only start them, and nowhere otherwise; files and folders always come last. Running a command adds no recent item or learned app usage, and the other tabs never search commands. Shortcut Coach palette history is read-only aside from its explicit confirmed clear-all action, so row selection never writes the pasteboard or mutates event state.

The keybumps.app website lives in `apps/web/` as an independent pnpm project (Next.js on Cloudflare Workers through OpenNext). It shares no code with the Mac app. The two depend on each other only through public URLs: the site's Download buttons and its `/download/` redirect read the release pointer at `updates.keybumps.app/latest.json`, and shipped app builds link to `https://keybumps.app/pricing` (`LicenseModels.swift`), so the site must keep that URL resolving. Its CI is `.github/workflows/web.yml`, and the macOS workflows ignore `apps/web/`. Release-please skips a commit only if every file it touches is under `apps/web/`, so website PRs change only `apps/web/**`, and a needed root change goes in a separate `chore:`, `docs:`, or `ci:` PR. The Mac app lives in `apps/macos/`, beside the website; `CHANGELOG.md`, `docs/`, the release-please files, and `brand/` stay at the repository root (`docs/adr/0003-mac-app-in-apps-macos.md`).
