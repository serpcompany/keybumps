# Architecture

`KeybumpsApp` and `AppModel` own composition and lifecycle. Feature services own behavior but never create another app delegate, status item, Settings scene, updater, license system, or launch-at-login controller.

`UpdateControlling` is the single app-shell update seam. The production adapter owns Sparkle's standard updater controller and exposes only customer-visible state/actions to `AppModel`, the native menu, and General settings. It explicitly opts into Sparkle's standard scheduled-update driver, which owns the linked release-notes and update presentation. Debug/test builds are disabled unless explicitly pointed at a credential-free, fragment-free loopback fixture feed. The shared `UpdateInstallationSafetyPolicy` is the one classification seam used by normal termination, synchronous Window Management commands, the full valid drag-to-snap mouse lifecycle, and Sparkle's supported relaunch-postponement callback; it combines Dictation phase with named app-owned critical operations, then resumes installation only when all are safe. The Screenshot Editor is the only unsaved-document workflow and reports `unsavedWork` while open; Clipboard, Quick Search, and Keyboard Shortcutter do not own unsaved work. Structural update telemetry records only stage, version/build, elapsed time, and categorized failure—never user content, filenames, identity, or keys. Release configuration embeds only the public feed URL and Ed25519 public key. The private key never enters the app or repository.

The shared `GlobalShortcutCoordinator` is the sole Carbon hot-key registrar. `AppPreferences` persists the editable Quick Search, Clipboard History, Dictation, and Window Management bindings; assigning one key combination removes it from any previous owner before the coordinator re-registers the complete valid set. During first-run onboarding only, `SpotlightShortcutConflictResolver` reads symbolic hot key 64 through the injected `SymbolicHotKeyPreferences` system boundary; when its enabled key and modifiers exactly match Quick Search, it preserves the entry and all siblings while disabling only that binding, asks macOS to reload symbolic hot keys, and retries Quick Search through `GlobalShortcutCoordinator`. Missing, malformed, unwritable, nonmatching, and completed-onboarding states fail closed or remain untouched as appropriate. Dictation temporarily registers unmodified Escape only while Recording or Transcribing can still be cancelled before insertion. `PermissionCoordinator` centralizes truthful permission state and recovery. Each capability stops its service and releases its shortcut when disabled. `ClipboardHistoryService` excludes only the exact pasteboard change written by automatic Dictation delivery, so a subsequent user copy—even of identical text—is still captured.

`MainWindowRouter` retains the SwiftUI Settings-window opener configured while the initial window is alive. The status menu and Command-comma use that route, so closing Settings does not remove the only listener capable of recreating it. `QuickSearchRouter` separately retains the command-palette opener used by Dock reopen and the status item. The app uses one SwiftUI `Window` scene and disables automatic macOS window tabbing, so Settings routes reuse the same window while Dock clicks default to Quick Search.

`DictationTranscriptionCoordinator` owns the lifecycle of the selected local Whisper runtime below the completed-audio transcription seam. It coalesces a model's concurrent cold load, reuses that one runtime for nearby Dictation and History retries, and evicts it after five idle minutes or model replacement/deletion; normal process teardown releases it at application termination. Apple Speech remains outside that cache, and loading a replacement waits for the previous large runtime to unload.

`CommandPaletteController` owns one floating keyboard-first surface for Quick Search, Clipboard History, Dictation History, and Keyboard Shortcutter History. Command-1/2/3/4 select those tabs in order; tab chrome uses only the shortcut and name. History inputs consistently say Search, and one shared native SwiftUI `ClearAllButton` owns the visible `Clear All` label and destructive confirmation behavior. Keyboard Shortcutter enablement, filtering, displayed rows, and keyboard selection derive from one content model; its rows are passive and Return does not copy or mutate history. All three histories are presented and cleared from this surface instead of duplicating history management in Settings. The palette tracks its confirmation as an internal presentation, so sheet focus changes and alert-button clicks do not trigger outside-click dismissal. Clipboard metadata retains bounded JSON persistence; image payloads live as separate files under Application Support so the index stays small and deletion/eviction can remove media independently. `DictationHistoryService` owns the independently stored `~/Documents/Keybumps/recordings/<timestamp>/meta.json` and `output.wav` pairs. It persists recording/transcribing/completed/interrupted/failed lifecycle state, suppresses recovery of sessions known to be live in the current process, and converts stale pending or legacy playable audio-only folders into retryable interrupted entries after relaunch. Shared dictation cards provide retry transcription and adjustable local playback in the palette.

`DictationAudioTransportView` is the single visual playback component for original and translated speech. `TranslatedSpeechPlayer` selects an installed locale-matched voice, renders speech into a temporary local WAV, and composes the shared `DictationAudioPlayer`; closing or changing the translation stops playback and deletes the temporary file. Translated audio never enters the durable per-recording archive.

Keyboard Shortcutter retains its donor separation between Detection, Delivery, Infrastructure, Domain, and Views. One typed shortcut registry converts complete sanitized AX tuples into the durable event values consumed unchanged by history, native copy, custom presentations, keycaps, accessibility output, and the inline Keyboard Shortcutter keyboard-symbol guide. The visible guide is a curated subset of Apple-documented menu symbols; broader runtime support does not automatically create repetitive or uncertain guide rows. Generic menu clicks resolve one exact enabled menu item from the hit ancestry, while Chrome tab actions poll the original application process for a bounded period so a moving button or one stale AX sample cannot lose the first verified action. Every preview executes the same production channel adapter as real delivery without writing a history event. When Sound is selected, previewing another presentation also invokes the production Sound adapter; direct Sound preview invokes it exactly once. The retained visual channels are Native macOS Banner, Top-right Toast, and Top-center Shelf. Unsupported legacy channel selections, including Pointer Card, are removed while loading preferences. Custom presentations share one per-channel session and one top-left close, cross-app Escape, screen-wide horizontal-trackpad-scroll, and hover-paused dismissal lifecycle; keyboard and scroll monitors exist only while at least one presentation is active. Sound is configured separately from visual presentation channels. Native notification authorization is reflected in Settings and the Dock attention badge when that channel is enabled. Window frame calculations and the Rectangle-inspired settings grouping/preview model remain pure and separately testable from Accessibility execution. Dictation owns no guide or assistant behavior.

`ScreenshotToolsService` owns the Screenshot Tools capability under `Keybumps/ScreenshotTools/`. `ScreenshotLocationResolver` reads the macOS screenshot location read-only and falls back to the Desktop; a directory dispatch source plus a periodic location check detect new files, and only files carrying macOS's screen-capture metadata that were created after watching began and whose size has settled are handed to `ClipboardHistoryService.ingestImageFile(at:)`. Clipboard History stores its own media copy plus the original `sourcePath`, never writes the pasteboard during ingestion, and never deletes the original. `AppModel` runs the watcher only while both Screenshot Tools and Clipboard History are enabled; injected test compositions use an inert directory reader so tests never touch real user folders. `ScreenshotEditorPresenter` opens at most one `ScreenshotEditorWindowController` from the Command Palette's Clipboard tab (Command-E or Command-click, wired only while Screenshot Tools is enabled). Annotations are value types in image points with snapshot undo; `ScreenshotAnnotationRenderer` is the single drawing path for both the canvas and export, rendering redactions from source pixels before marks and exporting at source pixel density. The open editor is reported to `UpdateInstallationSafetyPolicy` as `unsavedWork`. `AppPreferences` tracks known capabilities so a newly introduced capability is enabled once for existing installs and the owner's later choice is respected.

Quick Search owns a bounded local `RecentItemStore`. Only a successfully opened app, file, or folder becomes a recent item; opening it again moves the same URL to the front. The empty-search list opens the item directly and supports individual deletion plus confirmed Clear All. Revealing, highlighting, dismissing, failed opens, and ordinary typing do not add items. Keyboard Shortcutter palette history is read-only aside from its explicit confirmed clear-all action, so row selection never writes the pasteboard or mutates event state.
