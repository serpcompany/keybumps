# Issue #40: Argmax OSS Swift evaluation

Date: 2026-09-19

## Verdict

**Yes: evaluate WhisperKit before implementing direct `whisper.cpp`, and make WhisperKit the preferred integration if the English/Japanese fixture benchmark passes.** Keybumps is already an arm64-only macOS 14.2 app, which matches WhisperKit's strongest case: a native Swift Package Manager product, Core ML execution on Apple silicon, local completed-file transcription, explicit English/Japanese selection, and first-party model download/cache support. It should reduce integration work and fit the existing completed-WAV seam better than maintaining a C/C++/XCFramework boundary.

This is not an Apple translation model and it does not replace Keybumps' `TranslationSession`. `WhisperKit` converts speech to text. Its `.translate` task converts non-English **speech to English text**; it does not translate arbitrary transcript text between languages. The repository's other products are `TTSKit` (text to speech), `SpeakerKit` (speaker diarization), and the `ArgmaxOSS` umbrella library; Keybumps should depend only on `WhisperKit`, not the umbrella product. ([repository overview](https://github.com/argmaxinc/argmax-oss-swift/blob/ea872ffd35705aa757f33033500b9b0d40bd38df/README.md#L25-L39), [package products and dependencies](https://github.com/argmaxinc/argmax-oss-swift/blob/ea872ffd35705aa757f33033500b9b0d40bd38df/Package.swift#L15-L85), [task semantics](https://github.com/argmaxinc/argmax-oss-swift/blob/ea872ffd35705aa757f33033500b9b0d40bd38df/Sources/WhisperKit/Core/Configurations.swift#L130-L136))

## Fit for Keybumps

| Question | Finding |
|---|---|
| macOS and hardware | Argmax's public prerequisite is macOS 14+ and Xcode 16+. Although the package manifest declares macOS 13, the project describes the SDK as on-device speech AI for Apple silicon, defaults the encoder/decoder to CPU plus Neural Engine on macOS 14+, and enumerates M1 and M2/M3/M4 Macs—not Intel Macs—in its device recommendations. Keybumps' macOS 14.2, arm64-only target is compatible; this should not be treated as an Intel fallback. ([installation prerequisites](https://github.com/argmaxinc/argmax-oss-swift/blob/ea872ffd35705aa757f33033500b9b0d40bd38df/README.md#L86-L103), [Core ML compute defaults](https://github.com/argmaxinc/argmax-oss-swift/blob/ea872ffd35705aa757f33033500b9b0d40bd38df/Sources/WhisperKit/Core/Models.swift#L92-L117), [M-series model support](https://github.com/argmaxinc/argmax-oss-swift/blob/ea872ffd35705aa757f33033500b9b0d40bd38df/Sources/WhisperKit/Core/Models.swift#L1527-L1613)) |
| Integration | Add the repository as an SPM dependency and link the individual `WhisperKit` product. `WhisperKit` itself depends on the package's `ArgmaxCore`; `TTSKit` and `SpeakerKit` are not required. Its file API accepts WAV, MP3, M4A, or FLAC and returns transcription results. For long recordings, `.incremental` loading bounds audio-memory use and splits on VAD boundaries. ([SPM instructions](https://github.com/argmaxinc/argmax-oss-swift/blob/ea872ffd35705aa757f33033500b9b0d40bd38df/README.md#L86-L130), [local-file example and incremental loading](https://github.com/argmaxinc/argmax-oss-swift/blob/ea872ffd35705aa757f33033500b9b0d40bd38df/README.md#L140-L183)) |
| English and Japanese | Both are explicit language codes (`en`, `ja`). Use a multilingual model and pass the selected Keybumps language; `.en` variants are English-only. Multilingual `medium` is recognized by the runtime, but it is absent from Argmax's current recommended public table. ([language list](https://github.com/argmaxinc/argmax-oss-swift/blob/ea872ffd35705aa757f33033500b9b0d40bd38df/Sources/WhisperKit/Core/Models.swift#L1340-L1352), [multilingual variants](https://github.com/argmaxinc/argmax-oss-swift/blob/ea872ffd35705aa757f33033500b9b0d40bd38df/Sources/WhisperKit/Core/Models.swift#L36-L88), [recommended models](https://github.com/argmaxinc/argmax-oss-swift/blob/ea872ffd35705aa757f33033500b9b0d40bd38df/README.md#L185-L218)) |
| Offline behavior | Inference is local after the Core ML model and tokenizer are present. The default initializer is not strictly offline: it queries Argmax's Hugging Face repository, selects/downloads a device recommendation, and the tokenizer loader falls back to downloading from the upstream tokenizer repository when no local `tokenizer.json` exists. For Keybumps' no-network-during-transcription requirement, download deliberately, then initialize from an app-controlled local model folder with the tokenizer present; do not rely on `WhisperKit()` defaults. ([download/setup path](https://github.com/argmaxinc/argmax-oss-swift/blob/ea872ffd35705aa757f33033500b9b0d40bd38df/Sources/WhisperKit/Core/WhisperKit.swift#L168-L222), [local-folder versus download setup](https://github.com/argmaxinc/argmax-oss-swift/blob/ea872ffd35705aa757f33033500b9b0d40bd38df/Sources/WhisperKit/Core/WhisperKit.swift#L307-L355), [tokenizer fallback](https://github.com/argmaxinc/argmax-oss-swift/blob/ea872ffd35705aa757f33033500b9b0d40bd38df/Sources/WhisperKit/Utilities/ModelUtilities.swift#L17-L76)) |
| Model lifecycle | The SDK exposes a download base, model repository, model folder, progress callbacks, optional background download session, prewarming, load/unload state, and custom model repositories. Its Hub code checks LFS SHA-256 metadata, but the high-level WhisperKit API downloads the repository's default `main` revision and exposes no complete user-facing delete/update lifecycle. Keybumps must still own consent, available space checks, cancellation, installed version, rollback/removal, and a pinned manifest or snapshot policy. ([configuration](https://github.com/argmaxinc/argmax-oss-swift/blob/ea872ffd35705aa757f33033500b9b0d40bd38df/Sources/WhisperKit/Core/Configurations.swift#L7-L107), [high-level download path](https://github.com/argmaxinc/argmax-oss-swift/blob/ea872ffd35705aa757f33033500b9b0d40bd38df/Sources/WhisperKit/Core/WhisperKit.swift#L250-L301), [Hub hash checks](https://github.com/argmaxinc/argmax-oss-swift/blob/ea872ffd35705aa757f33033500b9b0d40bd38df/Sources/ArgmaxCore/External/Hub/HubApi.swift#L500-L573)) |

## Model choices for the benchmark

Use the current Argmax-recommended multilingual compressed Turbo as the first candidate: `large-v3-v20240930_626MB`. The hosted folder is 627 MB, Argmax recommends it across iOS and macOS for maximum multilingual accuracy, and it is the M1 default. `small` is 486 MB and is the useful lower-resource comparator. The uncompressed macOS Turbo folder, `large-v3-v20240930_turbo`, is 1.64 GB and is Argmax's maximum-speed/accuracy macOS option, but the current support map lists it for M2/M3/M4 and omits it on M1. A multilingual `medium` conversion exists and is 1.53 GB, and the runtime recognizes `medium`, but Argmax omits it from the current recommendation and device-support tables; treat it as hosted/legacy rather than a default candidate. ([Argmax model table](https://github.com/argmaxinc/argmax-oss-swift/blob/ea872ffd35705aa757f33033500b9b0d40bd38df/README.md#L185-L218), [M1 and M2+ support map](https://github.com/argmaxinc/argmax-oss-swift/blob/ea872ffd35705aa757f33033500b9b0d40bd38df/Sources/WhisperKit/Core/Models.swift#L1527-L1613), [compressed Turbo assets](https://huggingface.co/argmaxinc/whisperkit-coreml/tree/main/openai_whisper-large-v3-v20240930_626MB), [`small` assets](https://huggingface.co/argmaxinc/whisperkit-coreml/tree/main/openai_whisper-small), [full Turbo assets](https://huggingface.co/argmaxinc/whisperkit-coreml/tree/main/openai_whisper-large-v3-v20240930_turbo), [medium assets](https://huggingface.co/argmaxinc/whisperkit-coreml/tree/main/openai_whisper-medium))

Therefore the issue #40 comparison should be:

1. current Apple Speech baseline;
2. WhisperKit compressed Turbo (`large-v3-v20240930_626MB`);
3. WhisperKit `small` only as the lower-resource control;
4. WhisperKit full Turbo on M2+ only, and only if the extra roughly 1 GB of storage produces a meaningful latency or accuracy win;
5. Apple `SpeechAnalyzer` on macOS 26+ as already planned.

Do not carry forward a “Whisper Medium” row merely because it was proposed for a different runtime: the same model family has very different Core ML and GGML packaging, and Argmax does not recommend medium in its current public selection table.

## Licensing and maturity

Argmax OSS Swift is MIT-licensed, and the hosted WhisperKit Core ML model repository declares MIT. The SDK also vendors modified `swift-transformers` portions under Apache-2.0 and ships a `NOTICES` file; Keybumps must reproduce the applicable MIT and Apache notices in its third-party acknowledgements. ([SDK license](https://github.com/argmaxinc/argmax-oss-swift/blob/ea872ffd35705aa757f33033500b9b0d40bd38df/LICENSE), [third-party notices](https://github.com/argmaxinc/argmax-oss-swift/blob/ea872ffd35705aa757f33033500b9b0d40bd38df/NOTICES#L1-L26), [model repository](https://huggingface.co/argmaxinc/whisperkit-coreml))

The project is active enough for an evaluation dependency, not a hands-off subsystem: it has versioned releases through `v1.1.0` (2026-08-06), current main moved again on 2026-08-14, multiple CI workflows, and v1.1.0 added incremental loading plus several transcription fixes. Its release notes also document evolving defaults and deprecations. Pin an exact reviewed version for the prototype and upgrade intentionally. ([v1.1.0 release](https://github.com/argmaxinc/argmax-oss-swift/releases/tag/v1.1.0), [current commit](https://github.com/argmaxinc/argmax-oss-swift/commit/ea872ffd35705aa757f33033500b9b0d40bd38df), [CI workflows](https://github.com/argmaxinc/argmax-oss-swift/tree/ea872ffd35705aa757f33033500b9b0d40bd38df/.github/workflows))

## Decision boundary

Prefer WhisperKit for Keybumps because it is the narrower native integration for the app Keybumps actually ships. Keep direct `whisper.cpp` as the fallback choice if WhisperKit fails any of these gates: the approved Japanese/English fixtures, sustained record-to-insert latency and memory on the oldest supported M-series Mac, a fully controlled offline launch after installation, deterministic model versioning, or Developer ID distribution/signing. This repository review does not prove transcription quality; only the issue #40 fixture benchmark can approve the engine.
